### AdvancedRules Domain-Lab — Developer Documentation (Copy-Friendly)

### 1) System Overview

- What it is
    
    - AdvancedRules is an AI orchestration framework coordinating specialized AI personas (Product Owner, Planning, Principal Engineer, Codegen, Security, QA, Auditor, Documentation) to deliver a governed, auditable software development lifecycle.
        
- Main purpose
    
    - Provide a safety-first pipeline from planning to delivery with decision scoring, workflow gates, state management, and persistent artifacts in `memory-bank/`.
        
- Core components and architecture
    
    - Orchestrators and state:
        
        - `tools/orchestrator/trigger_next.py`: maps scored decisions to actionable commands (dry-run by default)
            
        - `tools/orchestrator/state.py`: idempotent state transitions backed by `workflow_state.json`
            
        - Post-run policy doc: `.cursor/rules/orchestrator_postrun.mdc`
            
        - Post-run executable: `tools/orchestrator_postrun.py`
            
    - Personas and roles:
        
        - `.cursor/rules/roles/*.md`: persona behaviors and responsibilities
            
    - Rules engine:
        
        - `.cursor/rules/**/*.mdc`: standardized rules with frontmatter (globs, priority, alwaysApply)
            
        - `tools/rules/{validate.py, mdc_linter.py, index_generator.py}`: validation and indexing
            
    - Memory & provenance:
        
        - `memory-bank/`: plan/business/reports/security/upwork/qa
            
        - `tools/artifacts/hash_index.py` → `memory-bank/artifacts_index.json`
            
        - `rule_attach_log.json` via `tools/rule_attach/detect.py`
            
    - Observability:
        
        - `tools/observability/aggregate.py` → `logs/observability/summary.{json,md}`
            
- How decision-making and workflow work
    
    - Candidates are generated by personas/orchestrations → scored by `tools/decision_scoring/advanced_score.py` using `weights.json` and `thresholds.json`
        
    - Gate policy:
        
        - NEXT_STEP (single winner) if confidence high
            
        - OPTION_SET for close mid-confidence candidates
            
        - ASK_CLARIFY on low confidence (or RISK_ALERT)
            
    - Destructive actions default to dry-run, require human approval
        
    - Trigger maps chosen candidate → command; `state.py` advances `workflow_state.json`
        
    - Artifacts, logs, and provenance are updated after each step

### 3) Workflow Documentation

- Validation phases (from `docs/VALIDATION_SUITE_STRUCTURE.md`)
    
    - Phase 0: Safety Rails
        
        - Validate `config/advanced_rules.yaml`
            
        - Ensure envelope v2 present; basic flow dry-run
            
        - Pass: safety flags + envelope v2 present
            
    - Phase 1: Planning Pipeline
        
        - `arx tasks plan` and `arx tasks print`
            
        - Pass: planner emits plan; printing works
            
    - Phase 2: Declarative Flows
        
        - Lint flow `feature_request_to_pr`, dry-run exec
            
        - Branch guard on `main/master`
            
        - Pass: lint pass; dry-run OK; main-guard respected
            
    - Phase 3: Memory / RAG
        
        - RAG disabled by default; enable path validated
            
        - Pass: default blocks; enabled path does not crash
            
    - Phase 4: Observability
        
        - Prometheus exporter up; counters > 0; P95 ≤ 1200ms
            
    - Phase 5: Queue / Concurrency
        
        - Redis + workers; process load; counters move; P95 ≤ 1200ms
            
- Decision scoring and orchestration
    
    - Scoring:
        
        - Run: `python3 tools/decision_scoring/advanced_score.py`
            
        - Inputs: candidates, weights (`weights.json`), thresholds (`thresholds.json`)
            
        - Outputs: ranked candidates, decision type (NEXT_STEP, OPTION_SET, ASK_CLARIFY, RISK_ALERT), trace
            
    - Trigger and state:
        
        - Trigger chosen action (dry-run by default): `python3 tools/orchestrator/trigger_next.py --dry-run`
            
        - Update `workflow_state.json` via `tools/orchestrator/state.py`
            
    - Provenance & observability:
        
        - `memory-bank/artifacts_index.json` updated
            
        - `tools/observability/aggregate.py` aggregates metrics → `logs/observability/summary.{json,md}`
            
    - Action Envelope v2 (clarification):
        
        - FlowRunner generates action envelope v2 at runtime
            
        - Samples: root `action_envelope.json`, `action_envelope_cmd.json`; v2 specimen: `tools/envelopes/action_envelope_v2.json`
            
- Integration with domains (rules)
    
    - Backend: Python, FastAPI, Node/Express, Java, Go, C#, Laravel, WordPress, Convex
        
    - Frontend: React, Vue, Svelte, SolidJS, Qwik, Next.js, Tailwind, HTMX
        
    - Mobile: Android, Flutter, React Native, NativeScript
        
    - Specialized: AI/ML, Blockchain, DevOps

### 4) Rules Engine Documentation

- Rules file format (frontmatter)
    

`--- title: "Technology Name — v1" description: "What the rules cover" globs: ["**/*.ext", "src/**/*.ext", "components/**/*.ext"] alwaysApply: false priority: high ---`

- How it works
    
    - `.mdc` rules declare scope via `globs`, set `priority`, and may set `alwaysApply: true` for base/global rules.
        
    - Orchestrator attaches applicable rules; `tools/rules/validate.py` and `tools/rules/mdc_linter.py` validate integrity and style.
        
- Domain-specific rules and purposes
    
    - Enforce technology best practices, coding standards, and patterns per stack.
        
    - Provide guardrails and guidance for personas during planning, implementation, and review.
        
- Decision gates and validation processes
    
    - Weighted factors (intent, state, evidence, recency, preference) yield a normalized score.
        
    - Gate thresholds:
        
        - High confidence → NEXT_STEP (single winner)
            
        - Mid confidence + small top-2 gap → OPTION_SET (2–3)
            
        - Low confidence → ASK_CLARIFY (or RISK_ALERT if risk elevated)
            
    - Destructive/compliance-sensitive actions:
        
        - Dry-run by default and require human approval (enforced by `config/advanced_rules.yaml`)
            

### 5) Setup and Usage Guide

- Environment requirements
    
    - Python ≥ 3.8, Node ≥ 18
        
    - Python packages (subset from `requirements.txt`):
        
        - pytest, pyyaml, networkx, chromadb, sentence-transformers, torch, transformers, prometheus_client, celery, redis
            
- Initialize and run
    
    - Quickstart (minimal happy path):
        
        - `python3 tools/prestart/prestart_composite.py`
            
        - Ensures upwork artifacts and preflight status
            
        - `python3 tools/quickstart.py`
            
        - Creates `memory-bank/plan/client_brief.md`, runs:
            
            - `product_owner_ai` → `planning_ai` → `auditor_ai` → `principal_engineer_ai --mode PEER_REVIEW` → `principal_engineer_ai --mode SYNTHESIS`
                
    - Manual role execution:
        
        - Ensure `memory-bank/plan/client_brief.md`
            
        - `python3 tools/run_role.py product_owner_ai`
            
        - `python3 tools/run_role.py planning_ai`
            
        - `python3 tools/run_role.py auditor_ai`
            
        - `python3 tools/run_role.py principal_engineer_ai --mode PEER_REVIEW`
            
        - `python3 tools/run_role.py principal_engineer_ai --mode SYNTHESIS`
            
- CLI (arx)
    
    - Flow:
        
        - `arx flow lint --flow=<flow_id>`
            
        - `arx flow run --flow=<flow_id> --task-id=<id>` (dry-run by default)
            
        - `arx flow render --flow=<flow_id>`
            
        - `arx flow list`
            
    - Tasks:
        
        - `arx tasks plan "<goal>"`
            
        - `arx tasks print [task_id]`
            
        - `arx tasks export [task_id]`
            
    - Memory:
        
        - `arx memory index --src=<path>`
            
        - `arx memory query --persona=<p> --q="<query>"`
            
        - `arx memory stats`
            
        - `arx memory purge --persona=<p>`
            
    - Observability:
        
        - `arx obs serve --port=<port>`
            
    - Safety notes:
        
        - All operations default to dry-run
            
        - Live execution requires `AR_ENABLE_FLOW_ENGINE=1`
            
- Validation suite (phases 0–5)
    
    - One-liner:
        
        - `bash scripts/validate_all.sh`
            
    - Make targets:
        
        - `make phase0` … `make phase5`, `make validate`, `make clean`
            
    - Phase highlights:
        
        - Phase 0: safety rails and envelope v2 checks; flow dry-run
            
        - Phase 1: task plan/print
            
        - Phase 2: flow lint + dry-run; main-guard
            
        - Phase 3: RAG off by default; enable path
            
        - Phase 4: metrics exporter, counters, P95 target
            
        - Phase 5: Redis + workers; load and throughput
            
    - Artifacts:
        
        - `.artifacts/metrics_phase4.txt`, `.artifacts/metrics_phase5.txt`
            
        - `logs/observability/summary.json|md`
            
- Decision scoring + trigger
    
    - Score next actions:
        
        - `python3 tools/decision_scoring/advanced_score.py`
            
    - Trigger (dry-run):
        
        - `python3 tools/orchestrator/trigger_next.py --dry-run`
            
    - Adjust weights/thresholds:
        
        - `tools/decision_scoring/weights.json`, `tools/decision_scoring/thresholds.json`
            
- Safety rails configuration (must-have in `config/advanced_rules.yaml`)
    
    - `dry_run_default: true`
        
    - `human_approval_required: true`
        
    - `branch_only_workflow: true`
        
    - Envelope v2 present: `tools/envelopes/action_envelope_v2.json` with `flow_id`, `task_id`, `step_id`
        
- Observability and queue
    
    - Metrics:
        
        - `python3 tools/observability/aggregate.py`
            
        - Prometheus endpoint (port as configured), counters > 0, track P95
            
    - Queue (Redis/Celery):
        
        - See `requirements.txt` for Redis/Celery
            
        - Validate with `scripts/phase5_queue.sh` (workers + load)
            
- NPM shortcuts (from `package.json` scripts)
    
    - `npm run start` → `python3 tools/quickstart.py`
        
    - `npm run prestart` → prestart composite
        
    - `npm run score` → decision scoring
        
    - `npm run orchestrate` → trigger next
        
    - `npm run observe` → observability aggregate
        
    - `npm run test` → pytest
        
    - `npm run lint` / `npm run format` / `npm run format:fix`
        
- Planning & audit presence checks
    
    - Planning output present: `memory-bank/plan/Action_Plan.md`
        
    - Audit output present: `memory-bank/plan/Summary_Report.md`
